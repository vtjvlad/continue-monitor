# Как устроен Continue Monitor (простыми словами)

## Зачем это нужно

Continue Monitor — это панель, которая показывает, что сейчас делает агент Continue CLI: жив ли процесс, насколько заполнен контекст, на какой стадии работы агент находится, чем закончились шаги и весь запрос, какие инструменты он недавно вызывал.

Панель только наблюдает. Она не запускает и не останавливает агента и ничего не меняет в его сессиях.

## Из чего состоит система

Есть две части.

**Сервер** работает в фоне как системный сервис на этой же машине. Он смотрит процессы Continue, читает файлы сессий на диске и собирает из этого понятный снимок состояния.

**Страница в браузере** раз в несколько секунд запрашивает этот снимок и рисует дашборд: статус, фазы, исходы, контекст, ленту действий.

Доступ к данным защищён токеном. Сервер слушает только локальный адрес машины, снаружи сам по себе не торчит.

## Откуда берутся данные

Система не получает от Continue готовый «статус агента». Она собирает картину из нескольких обычных источников:

- список процессов операционной системы — видно, запущен ли Continue и сколько он уже работает;
- индекс сессий Continue — какие сессии вообще есть;
- файл конкретной сессии — история сообщений, вызовы инструментов, сведения о токенах;
- настройки Continue — лимит контекста выбранной модели.

Активная сессия выбирается по рабочей папке процесса: если процесс сидит в каталоге проекта, берётся самая свежая сессия с этой же папкой.

## Что такое «фаза»

Фаза — это ответ на вопрос «чем агент занят прямо сейчас». На экране всегда подсвечена **одна** текущая фаза. Остальные видны как список возможных состояний, но **не заполняются по порядку** — это не шкала прогресса и не «пройденный путь».

Возможные основные фазы:

ожидание ввода → размышление → планирование → чтение файлов → анализ → согласование с человеком → ожидание подтверждения опасного действия → редактирование файлов → выполнение команд → ответ пользователю.

Если процесса Continue нет совсем, считается, что активного агента нет (`idle`).

Важно: Continue сам эти названия на диск почти не пишет. Монитор угадывает фазу по свежим следам — какие инструменты вызывались, есть ли незакрытое «размышление», похож ли текст на предложение вариантов, обновлялся ли файл сессии только что.

Отдельный нюанс: окно Continue даже в простое может слегка грузить процессор. Поэтому «агент реально работает» определяется в основном по тому, обновлялся ли файл сессии недавно (примерно за последние 20 секунд), а не только по загрузке CPU.

## Что такое «параллельные режимы» (оверлеи)

Кроме основной фазы есть четыре отдельных режима. Они не входят в список основных фаз и могут гореть одновременно с любой фазой и друг с другом:

- **Сжатие** — похоже, что агент сжимает или суммаризирует контекст;
- **Субагент** — запущен вложенный агент;
- **Skills** — используется механизм навыков Continue;
- **MCP** — вызывается внешний инструмент через MCP, а не встроенный tool Continue.

На экране они лежат **под** треком основных фаз. Пока режимы не активны, видны только фазы. Когда хотя бы один режим включается, его индикаторы **всплывают поверх** фаз и перекрывают их — так проще заметить, что параллельно с обычным шагом идёт что-то ещё.

## Что такое «исходы»

Исходы — это не «чем занят агент», а **чем закончилось** действие. Их три варианта: **Ready**, **Canceled**, **Error**. Они вынесены отдельно от основных фаз.

Есть два уровня:

### Запрос

Компактный блок **под** треком фаз. Показывает итог всего хода пользователя (с последнего сообщения пользователя до ожидания следующего ввода).

Загорается, когда ход уже завершён (агент снова ждёт, открытых tool-вызовов нет). Если в ходе были ошибки tool’ов — приоритет у **Error**, иначе у **Canceled**, иначе при нормальном ответе — **Ready**.

### Шаг

Блок **рядом с лентой действий**. Считает, сколько tool-шагов в текущем запросе закончились каждым вариантом:

- сколько **Ready** (успешно `done`);
- сколько **Canceled**;
- сколько **Error**.

Числа растут по мере работы. Дополнительно подсвечивается «текущий» исход последнего завершённого шага.

Так лента показывает *что* вызывалось, а блок «Шаг» — *чем эти вызовы закончились*.

## Что видит пользователь на экране

На главной карточке сверху вниз примерно так:

1. заголовок текущей задачи и крупный статус текущей фазы;
2. трек основных фаз (подсвечена только текущая) — при активных оверлеях их чипы перекрывают этот трек;
3. компактный блок **Запрос** (Ready / Canceled / Error);
4. кольцо контекста, процессы, модель, фрагмент «о чём думает»;
5. лента недавних tool-вызовов и рядом блок **Шаг** со счётчиками исходов.

Для ручной проверки фаз есть файл `PHASE-TEST-PROMPT.md` — готовый промпт для Continue CLI.

## Как считается заполнение контекста

Берётся последняя известная оценка размера запроса к модели в текущей сессии и делится на лимит контекста выбранной модели. Получается процент заполнения.

Намеренно не используется суммарный счётчик токенов за всю жизнь сессии — он завышает картину, потому что складывает много ходов подряд.

## Насколько этому можно доверять

Основной цикл агента (читает, правит, ждёт подтверждения, отвечает) обычно отражается хорошо, потому что Continue сохраняет вызовы инструментов в файл сессии. Исходы шагов тоже опираются на статусы этих вызовов (`done` / `canceled` / `errored`).

Слабее всего то, чего почти нет на диске: настоящее «сжатие контекста» внутри интерфейса Continue и мгновенные короткие состояния между сохранениями файла. Параллельный индикатор сжатия — лучшая доступная оценка, а не официальный сигнал от Continue.

Также пока нет накопления времени «сколько секунд агент провёл в каждой фазе» — есть только текущая фаза, счётчики исходов шагов по текущему запросу и общее время жизни процесса.

## Как это живёт на сервере

Сервис поднимается через systemd (`continue-monitor`), отдаёт страницу и защищённый статус-эндпоинт на `http://127.0.0.1:8788`. Браузер ходит к нему с токеном и сам обновляет картинку примерно раз в три секунды. Если сервис перезапустить после правок кода — подтягивается новая логика фаз, оверлеев, исходов и отображения.

## Короткий итог

Continue Monitor — это наблюдатель: он читает процессы и файлы Continue, собирает из них человекопонятную картину и показывает её на дашборде.

- **Фаза** — одна текущая занятость (не шкала прогресса).
- **Оверлеи** — параллельные режимы; при активации перекрывают трек фаз.
- **Запрос** — итог всего хода (Ready / Canceled / Error).
- **Шаг** — счётчики таких же итогов по tool-вызовам текущего запроса, рядом с лентой действий.

Управление агентом в эту систему не входит.
